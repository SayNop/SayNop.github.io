# 大模型API

llm 与 chat_model

  • llm 专门用于处理文本消息，仅接收文本内容，输出文本内容
  • chat_model 对聊天做了优化，输出更为复杂。通常采用消息列表，其中包含角色信息

# 接口规范

基本都遵循 OpenAI 规范。

请求时路径 /chat/completions，使用 jwt 认证，请求体为 json，指明模型，消息数组（内部声明角色和内容），响应消息是否为流式。

可选请求参数 temperature: 采样温度，取之范围 [0,2)。温度越高，每个词的概率越均匀，文本多样性越高。温度越低，概率越集中。精确判断时调低，创意性任务时调高（1.2算是比较高）

因此可使用 OpenAI 的 SDK 进行请求。但注意，使用老版本的写法。OpenAI SDK 新版本的调用方式出现较大变动，但兼容老版本

# 新版本调用方式的写法，国内模型不可用
from openai import OpenAI
client = OpenAI()
response = client.responses.create(
    model='gpt-5.4',
    input='Hello!'
)
print(response.output_text)

# 老版本调用方式的写法
from openai import OpenAI
client = OpenAI(
    api_key='',
    base_url='https://api.deepseek.com'
)
response = client.chat.completions.create(  # 请求体 json 的字段作为参数传入
    model='deepseek-chat',
    message=[{
        "role": "system",
            "content": "You are a helpful assistant."
        }, {
            "role": "user",
            "content": "Hello!"
    }],
    stream=False
)
# 响应json
print(response.model_dump_json())
# 响应json路径以点的方式进行访问
print(response.choices[0].message.content)

大模型的服务是无状态的。每次请求是一次会话，不同会话相互独立，不具备记忆能力

因此，需要在请求体的 messages 数组中拼接所有历史消息

执行能力更强，可以操作软件

# 智能体入门

在没有 Agent 时，大模型只能基于训练数据回答问题。例如在如果不打开搜索功能，询问大模型明天的天气，则只能从训练集中获取过去训练过的天气信息

测试编写一个查询天气的智能体

  • 安装依赖: uv add langchain 再安装对应大模型的依赖，例如

    • langchain-deepseek
    • langchain-openai
    • langchain-anthropic
    • langchain-google-genai
    • langchain-ollama
    • langchain-huggingface
    • langchain-aws

  • 定义工具

    from langchain.tools import tool
# 装饰器 - 声明该函数是一个工具，后续请求大模型时，会自动生成工具的请求 json 结构携带到请求体的 tools 字段中
@tool
def getWeather(location: str) -> str:
    # 测试时先返回固定天气
    return f'Current weather in {location} is sunny'

# 声明使用的模型 和 可调用的函数
agent = create_agent('deepseek-chat',  tools=[getWeather])
# 向大模型发送请求时的可选参数 tools, 用于告知模型有哪些工具可以调用

  • 调用 agent

    response = agent.invoke({
    'message': [{
        'role': 'user',
        'content': '杭州今天天气怎么样？'
    }]
})

智能体工作流程

  • 用户提问

  • 模型分析(思考 Reasoning): 是否需要调用工具，调用什么工具

    • 请求体 json 中的可选参数 tools 用于描述当前有哪些工具可以调用

  • 调用工具(行动 Action): 执行 思考 Reasoning 阶段制定的策略

    • 大模型响应的 choices 中除了拥有 message 文本信息外，还拥有 tool_calls 用于告知客户端 ai 想调用哪个工具。
    • langchain 作为客户端解析该结果并调用对应的工具，将调用结果返回给大模型
      for message in reponse['message']:  # 循环遍历消息列表，即对话历史记录
    print(message.model_dump_json(indent=2))

  • 感知分析(观察 Observation): 分析工具执行结果，是否足以完成目标，还是要继续调用工具

  • 生成结果

以上流程即为 ReAct

全称 Reasoning + Acting（推理 + 行动），智能体的核心思考和行动框架，是 Agent 像人类一样 思考问题、制定策略、执行行动、验证结果 的关键逻辑

不直接回答问题，而是按自然语言思考过程，选择工具并调用，一步步结合复杂问题。以上流程描述体现了 ReAct 的核心

# 模型调用

使用 model.invoke()（阻塞式） / model.stream()（流式），省略模型名、流式传输、温度等每次固定的参数，只需传输消息列表即可

response = model.invoke([{
    "role": "system",
    "content": "You are a helpful assistant."
}, {
    "role": "user",
    "content": "Hello!"
}])

如果只考虑单次提问，且无系统提示词，可直接使用 model.invoke('Hello!')

由于流式结果是生成器，访问流式结果需要 for in 循环遍历

  • stream 函数的参数 stream_mode='message: 模型返回的消息内容采用流式方式
    for chunk in stream:
    # 只打印响应体中的 content 字段内容，且不换行
    print(chunk.content, end='', flush=True)
  • stream 函数的参数 stream_mode='values: 对话消息历史采用流式方式。即每次得到的是当前轮次的的消息列表数组，数组在每轮中会添加最新消息
    for chunk in stream:
    # 获取当前轮次的消息数组
    current_msg_list = chunk['messages']
    # 从当前轮次消息数组中获取当前最新添加的消息
    latest_msg = current_msg_list[-1]
    if latest_msg.content:
        # 打印出消息种类(以此判断发送消息的角色) 和 消息内容
        print(type(latest_msg).__name__, latest_msg.content)
    try:
        # 仅 AIMessage 会携带需要调用工具的内容
        if latest_msg.tool_calls:
            # 打印出工具调用信息，可能会一次要求调用多个工具
            print(f"tools: {[tc['name'] for tc in latest_msg.tool_calls]}")
    except AttributeError:  # 仅 AIMessage 会携带需要调用工具的内容，其他消息无该属性
        pass

直接调用模型就是使用 invoke 或 stream 方法。而大多数情况下，不是直接调用大模型，而是在智能体中使用大模型

  • 创建智能体

    from langchain.agents import create_agent
# 方法 1: 传入创建好的 model
agent = create_agent(model=model)
# 方法 2: 指定模型名称，内部自己执行 init_chat_model 创建模型。因此也需要 langchain 官方支持模型的名称
agent = create_agent(model='deepseek-chat')

  • 调用智能体。同调用大模型一样，使用 invoke 或 stream 方法

    response = agent.invoke({
    # 智能体的请求体中可用的参数众多，传入消息时需要 `message` 字段明确说明传入的是消息
    'message': [{
        "role": "system",
        "content": "You are a helpful assistant."
    }, {
        "role": "user",
        "content": "Hello!"
    }]
})

messages = agent.stream({
    # 智能体的请求体中可用的参数众多，传入消息时需要 `message` 字段明确说明传入的是消息
    'message': [{
        "role": "system",
        "content": "You are a helpful assistant."
    }, {
        "role": "user",
        "content": "Hello!"
    }],
    # 指明流的模式。message 模式是常规的连续吐字模式
}, stream_mode='message')
for token, metadata in messages:
    # 检查是否有响应内容
    if token.content:
        print(token.content, end='', flush=True)
# stream_mode='values'时，遍历得到的是历史消息数组。
# 可观察到每次消息数组的变化，每次新增的内容。chunk['messages'][-1] 即是每次新增的消息

# 消息

有的消息使用 str，有的消息使用 list[dict]，此处介绍 langchain 常用的消息格式

消息存在多种类型类型

在 langchain 中，调用端与大模型间来回传输的消息，都被封装为 BaseMessage，且分为多个子类，每个子类对应不同角色类型的消息

  • SystemMessage Role: system
  • HumanMessage Role: user
  • AiMessage Role: assistant 即模型返回的消息
  • ToolMessage Role: tool 即工具调用后响应给大模型的消息

使用下列示例代码，观察传输的消息

from langchain.agents import create_agent
from langchain.tools import tool

@tool
def get_weather(location: str) -> str:
    return f'Current weather in {location} is sunny'

# 使用 langchain 官方支持的模型名称直接创建智能体，而不是传入模型实例的方式
agent = create_agent(model='deepseek-chat', tools=[get_weather])

from langchain_core.messages import SystemMessage, HumanMessage, AIMessage

response.agent.invoke({
    'message': [
        # 等效为 {'role': 'system', 'content': '你是一个 AI 助手'}
        SystemMessage(content='你是一个 AI 助手'),  # 关键字 content 可以省略
        # 等效为 {'role': 'user', 'content': '你好，我是用户'},
        HumanMessage('你好，我是用户')
        # 等效为 {'role': 'assistant', 'content': '你好，用户！请问有什么需要帮忙的？'},
        AIMessage('你好，用户！请问有什么需要帮忙的？')
        # 等效为 {'role': 'user', 'content': '上海今天天气怎么样？'}
        HumanMessage('上海今天天气怎么样？')
    ]
})
print(response)
# 遍历消息
for message in response['messages']:
    message.pretty_print()

# 得到以下输出：

# ============== System Message ==============
# 你是一个 AI 助手
# ============== Human Message ==============
# 你好，我是用户
# ============== AI Message ==============
# 你好，用户！请问有什么需要帮忙的？
# ============== Human Message ==============
# 上海今天天气怎么样？
# ============== AI Message ==============
# 我来帮你查询一下上海今天的天气情况
# Tool Calls
#   get_weather (call_00_xxxx)
#  Call ID: call_00_xxxx
#   Args:
#     location: 上海
# ============== Tool Message ==============
# Name: get_weather
#
# Current weather in 上海 is sunny
# ============== Ai Message ==============
# 根据查询结果，上海进行的天气是晴朗的

还可以进一步简化。此时不同点是，Message类会在实例化时直接得到实例，元组则是 langchain 读取到该元组后动态转换成 Message 示例

# {'role': 'system', 'content': '你是一个 AI 助手'}
# SystemMessage(content='你是一个 AI 助手')
('system', '你是一个 AI 助手')

# {'role': 'user', 'content': '你好，我是用户'}
# HumanMessage('你好，我是用户')
('human', '你好，我是用户')

# {'role': 'assistant', 'content': '你好，用户！请问有什么需要帮忙的？'}
# AIMessage('你好，用户！请问有什么需要帮忙的？')
('ai', '你好，用户！请问有什么需要帮忙的？')

# 该方式便于链式调用时注入变量，因为是动态转换的，链式调用模型时才会进行替换并转换
('system', '今天天气是{weather}')

除了发送方不一致导致的 Base Message 子类不同。Langchain 还支持向模型发送多模态消息（Multimodal），比如图片、音频、视频、文本等。

但需要提前确认所使用的模型是否支持多模态

查看 langchain 官网的 Integrations 接入页面的 Chat models 查看模型是否支持多模态（模型的 Multimodal 一栏是否打勾）

比如 deepseek、ollama 等不支持多模态

下面以图片为例，说明如何发送图片消息

from langchain.chat_models import init_chat_model

model = init_chat_model(
    model='qwen3.5-plus',  # 根据 qwen 官网，该模型支持图片、视频的输入
    model_provider='openai',  # 由于 langchain 不支持 qwen，但 qwen 兼容 openai。因此伪装成 openai
    base_url=os.getenv('DASHSCOPE_BASE_URL'),
    api_key=os.getenv('DASHSCOPE_API_KEY')
)
# 由于是非 langchain 官方支持的模型，使用模型实例构建智能体
agent = create_agent(model=model)

# 方式一：以图片链接的形式发送图片，内容需要是数组
# {'role': 'user', 'content': [
#     {'type': 'text', 'text': '图片描述'},
#     {'type': 'image', 'url': 'https://xxxx'}
# ]}
message = HumanMessage([  # content 直接传入内容数组
    {'type': 'text', 'text': '图片描述'},
    {'type': 'image', 'url': 'https://xxxx'}
])
# 方式二：将图片转换成 base64 编码 - 此方式请求体过大，会浪费 token
# {'role': 'user', 'content': [
#     {'type': 'text', 'text': '图片描述'},
#     {'type': 'image', 'base64': 'xxxx', 'mime_type': 'image/jpeg'}
# ]}
img_b64 = base64.b64encode(image_bytes).decode('utf8')
message = HumanMessage([  # content 直接传入内容数组
    {'type': 'image', 'base64': img_b64, 'mime_type': 'image/jpeg'},
    {'type': 'text', 'text': '描述一下图片内容'}
])

# 传入消息数组，注意流式调用需再传入流式模式
stream = agent,stream({'message': [message]}, stream_mode='message')
for chunk, metadata in stream:
    if chunk.content:
        print(chunk.content, end='', flush=True)

# 提示词工程

所有发送给大语言模型的消息都是提示词

消息数组中发送的 SystemMessage 就是系统提示词。

最简单的发送方法时在消息数组内添加 SystemMessage，后续聊天内容追加在数组内

由于系统提示词作为系统指令，每次都出现在消息数组中，有些麻烦。langchain 推荐在创建智能体时使用 system_prompt 参数而不是消息数组内的 SystemMessage 来传递系统提示词

from langchain.agents import create_agetn
agent = create_agent(model='deepseek-chat', system_prompt='你是一个智能助手，以简短的中文回答用户问题')

# 后续向智能体传递消息时，消息数组内无需 SystemMessage

提示词工程，指通过优化提示词使模型输出的结果更符合业务需要的过程。所以提示词需要反复调试，不断迭代。

系统提示词需要包含的部分，按以下顺序排列

  • 身份角色：描述AI指责、沟通风格、总体目标
  • 指令说明：（身份角色的补充）指导模型如何生成所需响应，应遵循的规则，应该做什么，不能做什么。指定任务的步骤，详细说明
  • 对话示例：提供输入示例和期望输出
  • 背景信息（可选）：额外补充信息。使用参考文本，让模型用参考文本作答。让模型从指定文本中筛选出答案，而不是自己造答案。如 RAG 中的知识库数据

推荐编写格式是 md 或 xml，使用分隔符标明输入的不同部分

  • 角色和指令：只设置身份角色可能不符合需求。比如明确说明指令部分，简单告知只需要做什么，不需要做什么，可以节省 token
    # 角色
- 你是一个编程助手，给用户提供 python 代码
# 指令
- 不要返回说明信息，仅返回代码内容
- 仅保留关键代码的注释
  • 对话示例：Few-Shot examples 是一种为模型提供示例的方法（Few-Shot Learn, 少样本学习）。提供的示例中，答案风格也会影响 AI 输出。简洁的答案示例可以避免输出内容过多，实现节省 token
    # 角色
- 你是一个地理老师，告知用户地理相关问题的答案
# 示例
user: 中国的首都是哪座城市
assistant: 北京

user: 山东的省会是哪里
assistant: 济南
  • 结构化输出：很多时候需要 ai 返回结构化内容，如 json / xml 等。便于代码操作。可通过指令与示例详细说明

    • 常规方式

      # 角色
- 你是一个地理老师，告知用户地理相关问题的答案
# 指令
- 务必保证以 json 格式输出，携带省份与城市信息
# 示例
user: 少林寺在哪个城市
assistant: 
{
    "province": "河南",
    "city": "郑州"
}

user: 泰山在哪里
assistant:
{
    "province": "山东",

# 链

组件串联，将前一项组件的输出作为后一项组件的输入。

Runnable 的子类拥有 invoke 与 stream 方法，比如消息模版，模型都是 Runnable 子类

Runnable 子类对象可以入链，因此可以编写 chain = prompt_template | model

prompt_template = PromptTemplate.from_template(
    '我的邻居姓{lastname}，刚生了{gender}，帮忙起名字，请简略回答'
)
chain = prompt_template | model
# 在此例中，dict 作为链的原始输入，给到 prompt_template，输出 PromptValue 实例。该实例又作为 model 的输入，给到模型对象
chain.invoke(input={'lastname': '张', 'gender': '女儿'})

本质上，即 Runnable 重写了 __or__ 方法，返回 RunnableSquence，每一项都会追加到 RunnableSquence 中

# 输出解析器

将 chat_model 回复的结果再交给 chat_model 进行提问，由于 chat_model 的输出是 AIMessage， chat_model 第二次收到消息是 AIMessage，此时会产生异常

即 chain = prompt | model | model 这个链在调用 invoke / stream 时会报错，仅接收 提示词实例 / str / 消息列表

可使用输出解析器处理模型的输出，使其可以作为模型的输入。例如 StrOutputParser 可将模型输出处理成简单字符串

  • StrOutputParser: 将传入的 Message 实例转换成 str
    from langchain_core.output_parsers import StrOutputParser
parser = StrOutputParser()
chain = prompt | model | parser | model

链中存在不止一次模型，即为多模型执行链。在实际情况下，模型的输出内容不会直接作为模型的输入，而是先进行数据处理，放入提示词模版，再提交给模型

由提示词模版通常需要 dict 类型，因此第一个模型的输出需要转换为 dict 类型，可使用 JsonOutputParser

  • JsonOutputParser

from langchain_core.chat_history import BaseChatMessageHistory
# list[BaseMessage] 与 list[dict] 互相转换的方法
from langchain_core.messages import messages_from_dict, message_to_dict

class FileChatMessageHistory(BaseChatMessageHistory):
    def __init__(self, session_id: str, storage_path: str):
        self.session_id = session_id   # 调用时指定的 session_id
        self.storage_path = storage_path  # 消息历史 json 文件的存储目录
        self.file_path = os.path.join(self.storage_path, self.session_id)  # 消息历史 json 文件路径
        os.makedirs(os.path.join(self.storage_path), exist_ok=True)  # 检测文件目录
    
    @property
    def messages(self) -> list[BaseMessage]:
        """获取指定会话的消息列表"""
        try:
            with open(self.file_path, 'r', encoding='utf-8') as f:
                messages_data = json.load(f)
            return messages_from_dict(messages_data)  # list[BaseMessage] -> list[dict]
        except FileNotFoundError:
            return []
    
    def add_message(self, messages: Sequence[BaseMessage]) -> None:
        """指定会话中追加最新消息"""
        all_messages = list(self.messages)
        all_messages.extend(messages)  # 通常需要追加的是一问一答

        serialized = [message_to_dict(message) for message in all_messages]  # 转换成 list[dict]，后续可 json.dump
        with open(self.file_path, 'w', encoding='utf-8') as f:
            json.dump(serialized, f)
    
    def clear(self) -> None:
        """清空指定会话内的消息记录"""
        with open(file_path, 'w', encoding='utf-8') as f:
            json.dump([], f)

    # 由于 FileChatMessageHistory 内部已经处理了会话不存在的情况，直接返回
    return FileChatMessageHistory(session_id, './chat_history/')

# agent 记忆的分类

langchain 自带记忆管理功能（本质上是 langgraph 自带的，langchain 基于 langgraph）。agent 的记忆分两类

  • 短期记忆：当前任务或会话的上下文。例如：对话历史，查询结果，任务状态
  • 长期记忆：跨任务或会话的经验与知识。例如：知识库，用户偏好，失败经验

# checkpointer

其中，短期记忆是通过 AgentState 实现的，会话历史是 AgentState 的一部分。会话历史是 AgentState 已经实现的，其他短期记忆内容需要自行实现 AgentState。

Langchain 提供了 Checkpointer 对象来保存 AgentState，每次用户与 AI 交互都会生成一个快照，记录为 checkpointer

同一个会话的多个 checkpointer 形成一个组，用同一个 thread_id 标记（实际含义同会话 id）

如果想给智能体添加短期记忆，需要在创建智能体时指明一个 checkpointer

  • 实例化 checkpointer
  • 创建 agent 时传入 checkpointer 实例
  • 调用 agent 时，指定一个自定义的 thread_id

# 记忆策略管理

由于随着会话推进，消息越来越多。而大模型一次接收的上下文有限，如果超出大小，则出现截取，即记得后面的，忘记前面的。

langchain 提供了记忆管理的策略open in new window来解决这个问题。

  • 修剪（Trim）：移除消息数组中的前 N 或后 N 条消息，再进行发送。会有记忆丢失
  • 删除（Delete）：删除 AgentState 快照。即该会话的历史消息直接清除
  • 总结摘要（Summarize）：将早期的历史消息进行总结，得到消息摘要，替换消息数组中被总结的消息。需要使用 LLM 做总结摘要模型
    from langchain.agents.middleware import SummarizationMiddleware  # 总结摘要中间件

agent = create_agent(
    model='gpt-4.1', 
    # 配置智能体的中间件
    middleware=[
        # 消息摘要中间件的实例化
        SummarizaionMiddleware(
            model='gpt-4.1-mini',  # 总结摘要模型 
            trigger=('tokens', 4000),  # 触发总结的方式: fraction - 达到模型最大 token 的百分比 / tokens - 按 token 数 / messages - 按消息输 
            keep=('messages', 20)  # 保留多少条消息
        )
    ])
  • 自定义（Custom）：用户自定义策略，比如对消息进行筛选后传递

# 中间件

中间件实现了拦截。总结摘要中间件 SummarizationMiddleware 本质是将输入的提示词进行拦截，获取传入的历史消息数组，检测是否需要进行压缩，并根据初始化时的参数对历史消息数组进行压缩。

除了 langchain 自带的中间件，也可以自定义中间件。使用内置的装饰器 langchain.agent.middleware 定义中间件，不同拦截时机的装饰器分类如下

  • 节点式钩子（执行点顺序拦截）
    • @before_agent: agent 执行之前拦截
    • @after_agent: agent 执行之后拦截
    • @before_model: model 执行前拦截
    • @after_model: model 执行后拦截
  • 针对工具和模型的包装式钩子(替换对应的步骤)
    • @wrap_model_call: 每个模型调用时拦截
    • @wrap_tool_call: 每个工具调用时拦截

以下是自定义中间件示例，注意参数

from langchain.agent.middleware import before_agent, wrap_model_call, wrap_tool_call
from langchain.agents import AgentState
from langchain.runtime import Runtime

# 节点式钩子 的参数固定为 state: AgentState, runtime: Runtime, 返回值为空
@before_agent
def log_before_agent(state: AgentState, runtime: Runtime) -> None:
    # 在 agent 执行前自动调用该函数，并传入 state 与 runtime
    # runtime.context 就是上下文，是一个 dict
    print(f"要开始调用智能体了，附带的消息个数是{len(state['messages'])}")  # state['messages'] 即为传递给智能体的历史消息数组

from langchain.tools.tool_node import ToolCallRequest
from langchain_core.messages import ToolMessage
from langgraph.types import Command

# 包装式钩子 的参数固定为 request(模型调用的请求), handle(处理对象), 需要手动指定让处理函数处理请求。
@wrap_model_call
def model_call_hook(request: ToolCallRequest, handler: Callable[[ToolCallRequest], ToolMessage | Command]) -> ToolMessage | Command:
    print('模型在调用')
    # request.runtime 就是 Runtime
    return handler(request)  # 模型调用的过程会被替换成该函数的内容，返回处理请求结果，使模型正常调用

@wrap_tool_call
def tool_call_hook(request, handler):
    print(f"调用了工具: {request.tool_call['name']}, 传入的参数是 {request.tool_call['args']}")
    return handler(request)

根据日志顺序可知，执行顺序如下，可选内容是调用工具的部分

before_agent-> before_model -> model_call_hook -> after_model [-> tool_call_hook -> before_model -> model_call_hook -> after_model] -> after_agent

        elif isinstance(msg, AIMessage):

# RunnablePassthrough

根据以上流程，向量检索的召回步骤是单独提炼出来，在 chain 外运行的。这是由于向量存储对象不是 Runnable 的子类，无法放入链中

此时可使用 RunnablePassthrough 类将检索流程入链

  • 场景一：透传输入（保持原始值不变）。当你的下游步骤需要原始输入，而并行分支需要处理该输入时，使用 RunnablePassthrough() 透传
    # 经典的 RAG 检索链
chain = ({
    "context": retriever,               # 分支 1：拿着 question 去检索出文档
    "question": RunnablePassthrough()   # 分支 2：把输入的 question 原封不动透传给 Prompt。本质就是个占位符，会替换为上一步传入的内容
} | prompt | model | StrOutputParser())

chain.invoke("什么是 LangGraph？")
  • 场景二：RunnablePassthrough.assign()（在字典中动态追加字段）。如果你的输入本身就是一个字典，你只想在保留原有所有 key 的同时，动态追加一些新的衍生字段，assign() 是最优雅的标准方案
    chain = (
    RunnablePassthrough.assign(
        context=lambda x: retriever.invoke(x["question"])  # 追加 context 字段，保留原有的 question
    ) | prompt | model)

def check_md5(md5_str: str) -> bool:
    """检测传入的 md5 是否已经被处理"""
    if not os.path.exists(config.MD5_PATH):  # 使用一个文件存储已处理的 md5
        open(config.MD5_PATH, 'w', encoding='utf8').close()  # 不存在则创建该文件
        return False
    with open(config.MD5_PATH, 'w', encoding='utf8') as f:
        for line in f.readlines():  # 检测文件中是否存在该 md5 值
            if md5_str == line.strip():  # strip 移除末尾的换行
                return True
    return False

def save_md5(md5_str: str):
    """将传入的 md5 标记为已处理"""  # 使用一个文件存储已处理的 md5
    with open(config.MD5_PATH, 'w', encoding='utf8') as f:
        f.write(md5_str + '\n')

def get_string_md5(md5_str: str, encoding='utf-8') -> str:
    """计算传入内容的 md5"""
    return md5(str(_in).encode()).hexdigest()

        :return: 处理结果的文本消息
        """
        # 检测原始文本内容是否已经被处理

class RagService:
    def __init__(self):
        self.vector_service = VectorStoreService(
            embedding_model=DashScopeEmbeddings(model='text-embedding-v4')
        )
        self.prompt_template = ChatPromptTemplate.from_messages([
            ('system', '你是一位知识助手，请根据已知参考材料回答用户的问题，生成简洁准确的答案。相关片段: {context}'),
            ('user', '用户问题：{input}')
        ])
        self.chat_model = ChatTongyi(model='qwen3-max')
        self.chain = self.__get_chain()

    def __get_chain(self):
        retriever = self.vector_service.get_retriever()

        # 处理 vector_store 查询数据库返回的 list[Document]，使其可以被后续环节作为输入
        def format_document(docs: list[Document]) -> str:
            if not docs: return '无相关参考资料
            return [f'\n- {doc.page_content}' for doc in docs]  # 将召回内容拼接成带有一定格式的字符串

        chain = ({
            'input': RunnablePassthrough(),
            'context': retriever | format_document  # 该子链最终返回字符串，作为后续提示词模版的内容注入
        } | self.prompt_template | self.chat_model | StrOutputParser())

        return chain

from .file_history_store import get_history

def __get_chain(self):
    retriever = self.vector_service.get_retriever()

    def format_document(docs: list[Document]) -> str:
        if not docs: return '无相关参考资料
        return [f'\n- {doc.page_content}' for doc in docs]

    def format_for_retriever(input_dict: dict) -> str:
        return input_dict['input']  # 传入用户问题的占位符

    def get_prompt_input(input_dict: dict) -> list[dict]:  # 构造系统提示词的输入
        return {
            'input': input_dict['input']['input'],  # 先取出穿透字典，再从中取出对应内容
            'history': input_dict['input']['history'],  # 先取出穿透字典，再从中取出对应内容
            'context': input_dict['context']
        }

    chain = ({ # 由于是历史消息转换链，传入内容是 dict，而不是 str
        'input': RunnablePassthrough(),  # 此时穿透的内容是 {'input': '<用户问题>', 'history': [<消息数组>]}
        # 子链的第一项需要将 dict 处理成用户问题 str，向量存储对象才能进行相似度搜索
        'context': RunnableLambda(format_for_retriever) | retriever | format_document  
    } 
    | RunnableLambda(get_prompt_input) | self.prompt_template  # 由于提示词现在需要处理三个占位符，原本的 dict 已无法使用
    | self.chat_model | StrOutputParser())

    return RunnableWithMessageHistory(
        chain,
        get_history,
        input_messages_key='input',
        history_message_key='history'  # 历史消息占位符
    )

    class VectorStoreService:
    def __init__(self):
        self.vector_store = Chroma(  # 向量存储实例
            collection_name=chroma_conf["collection_name"],
            embedding_function=embed_model,
            persist_directory=get_abs_path(chroma_conf["persist_directory"]),
        )
        self.spliter = RecursiveCharacterTextSplitter(  # 文档分割器
            chunk_size=chroma_conf["chunk_size"],
            chunk_overlap=chroma_conf["chunk_overlap"],
            separators=chroma_conf["separators"],
            length_function=len,
        )

    def get_retriever(self):  # 获取向量存储对象
        return self.vector_store.as_retriever(search_kwargs={"k": chroma_conf["k"]})

    def load_document(self):  # 加载文档函数，调用此函数会自动加载需求文档
        def check_md5_hex(md5_for_check):  # 检测是否已加载过该文档
            if not os.path.exists(get_abs_path(chroma_conf["md5_hex_store"])):
                open(get_abs_path(chroma_conf["md5_hex_store"]), "w", encoding="utf-8").close()
                return False
            with open(get_abs_path(chroma_conf["md5_hex_store"]), "r", encoding="utf-8") as f:
                for line in f.readlines():
                    line = line.strip()
                    if line == md5_for_check:
                        return True
            return False

        def save_md5_hex(md5_for_save):  # 标记已加载过的文档
            with open(get_abs_path(chroma_conf["md5_hex_store"]), "a", encoding="utf-8") as f:
                f.write(md5_for_save+"\n")

        def get_file_documents(read_path: str):  # 加载文档
            if read_path.endswith("txt"):
                return txt_loader(read_path)
            elif read_path.endswith("pdf"):
                return pdf_loader(read_path)
            elif read_path.endswith("csv"):
                return csv_loader(read_path)
            else:
                return []

        allowed_files_path = listdir_with_allowed_type(  # 获取指定后缀的文件
            get_abs_path(chroma_conf["data_path"]),
            tuple(chroma_conf["allow_knowledge_file_type"])
        )

        for path in allowed_files_path:
            md5_hex = get_file_md5_hex(path)
            if not md5_hex:  # 处理MD5计算失败的情况
                logger.warning(f"[加载知识库] {path} MD5计算失败，跳过")
                continue

            if check_md5_hex(md5_hex):
                logger.info(f"[加载知识库] {path} 内容已经存在于知识库，跳过")
                continue
            try:
                documents: list[Document] = get_file_documents(path)
                if not documents:
                    logger.warning(f"[加载知识库] {path} 无有效文本内容，跳过")
                    continue
                split_document: list[Document] = self.spliter.split_documents(documents)
                if not split_document:
                    logger.warning(f"[加载知识库] {path} 分片后无内容，跳过")
                    continue

                self.vector_store.add_documents(split_document)
                save_md5_hex(md5_hex)
                logger.info(f"[加载知识库] {path} 内容加载成功")
            except Exception as e:
                logger.exception(f"[加载知识库] {path} 加载失败")
                continue

    class ReactAgent(object):
    def __init__(self):
        self.agent = create_agent(
            model=chat_model,

            tools=[rag_summarize, get_weather, get_user_location, get_user_id, get_current_month,

    def execute_stream(self, query):  # 传入用户的提问
        input_dict = {
            "messages": [
                {"role": "user", "content": query},
            ]
        }
        # 传入上下文 dict，方便后续在中间件进行上下文注入
        for chunk in self.agent.stream(input_dict, stream_mode="values", context={"report": False}):
            latest_message = chunk["messages"][-1]  # 有历史记录所以取最后一条
            if latest_message.content:
                yield latest_message.content.strip() + "\n"
